# Epic E-ORG：移动硬盘原始媒体统一整理

日期：2026-11-04。状态：规划，未实现，不授权对现有硬盘执行写入。关联alpha.5 A5-01–32及U05/U06/U07/U08。

## 目标与边界

作为拥有多块移动硬盘的用户，我希望将散落的媒体盘点、识别、归组并生成可审阅的统一目录方案；确认后再选择整理，断盘或失败时能追踪和恢复，片库资料不丢失。

区分三层：物理文件、影片/版本/分段关系、目录合集展示。整理原文件不等同修改影片关系；合集也不强制变成同片版本。默认只读、原位使用仍可选。不是下载器、云盘同步器或自动空间清理工具。

现有只读约束继续有效。本Epic规划可选写能力，不自动修改AGENTS或当前权限。写入阶段需另行完成ADR、故障测试和明确的产品授权流程；用户批准具体计划后才执行。

## alpha.5 新增范围

- 必交付：F01–F05，设备/文件盘点、身份识别、重复与归属判断、规则、只读整理预览；F09的盘点/预览测试与隐私要求。
- 条件试点：F06仅复制到独立目标目录，保留源文件；依赖A5任务/备份/恢复门槛。未通过就延期，不强塞发布。
- 后续：F07索引绑定随复制试点一起验证；F08原地重命名、同盘移动、跨盘搬迁及回退执行独立评审，不默认纳入alpha.5。

验收口径：盘点能说明有哪些文件、属于哪个设备；每条建议有来源、冲突和目标路径；预览不改变源文件字节/名称/位置。没有匹配把握的内容保留原名或进入待确认，不能猜测后批量改名。

## F01 · 设备与目录盘点（P0，alpha.5）

|Story|用户故事|验收条件|
|---|---|---|
|ORG-01|我能登记多块硬盘并给它们起别名|显示卷标、文件系统、容量和在线状态；盘符不是唯一设备标识；不支持稳定标识时要求用户确认映射|

|ORG-03|我能中断后继续盘点|持久任务、扫描错误明细；单文件权限失败不结束全盘；增量变化可追溯|
|ORG-04|我能查看未连接硬盘的上次目录|明确快照时间及离线状态；离线不当作文件删除；不执行路径操作|

## F06 · 安全复制执行（P0前置门槛，alpha.5条件试点）

|Story|用户故事|验收条件|

|ORG-21|我能明确确认一份复制计划|仅执行勾选且仍有效的计划；复制源不删除；目标必须独立且不位于源扫描树内；防止递归复制|

不承诺一键断点续传所有文件系统。首次试点可按文件重试，但必须不重复提交、不破坏已有目标。

## 数据与任务设计建议（需ADR后实现）

实体：设备/位置、盘点快照、文件身份、资源组、规则版本、整理计划及版本、计划条目、执行步骤与校验记录。路径是位置，不是作品身份；设备身份无法可靠判断时要求用户映射。

状态：草稿 → 预检 → 待确认 → 已确认 → 执行 → 校验 → 提交 → 完成/部分失败。另有取消/中断/源变化/等待设备/冲突。每一步有幂等键；日志持久化失败不得继续破坏性操作。

复用A5统一任务、排除政策、备份/恢复和脱敏诊断；不要另建孤立进程内任务系统。候选模块为storage_inventory、organization_planner、organization_executor；名称是规划，不是当前实现。

## 发布门槛与依赖

alpha.5首批：ORG-01–20、32–35（其中设备实机验证只对实际测试环境承诺）。ORG-21–27须先通过A5-01–09、19–26及ADR/故障测试；未通过则只发布预览能力。ORG-28–31后续独立排期。

无论是否启用执行，原位片库都必须继续工作。不得在版本文档将“可生成计划”写成“已能安全搬迁”。范围新增需要在alpha.5进度表单独跟踪，不降低既有P0可靠性验收。
