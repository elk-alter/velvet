# 内置自动刮削：第一批移植

Velvet 现可直接执行移植自 Amane 的采集器，不必为此另外运行 Amane。当前已移植 JavBus、Jav321、FC2、FC2Club、FC2PPVDB、Freejavbt、Airav、XCity、JavDB 和 JavLibrary 十个采集器的解析与查找流程，不包含 Amane 全套来源、浏览器后端、翻译、智能体或文件整理功能。上游基线及修改声明见 [NOTICE](../NOTICE)。

## 使用

1. 在项目目录执行 `python -m pip install -r requirements.txt`，然后启动 Velvet。
2. 打开“资料源与目录”，选择“内置刮削 · 第一批来源”。已有外部刮削任务须先完成或取消，才能切换引擎。
3. 需要代理时填写 HTTP 代理地址，例如 `http://127.0.0.1:10808`，保存刮削配置。内置引擎不继承系统代理，留空表示直连；当前不支持 SOCKS 或带账号密码的代理配置。
4. 在任务页开启自动刮削，即会按现有限额处理未匹配、有编号的文件；同编号多文件共用一次任务。建议先暂停自动刮削，选一两个条目手动验证，再开启全库自动处理。

现有安装保留外部模式，避免升级后意外更换资料来源。Docker 构建会安装采集依赖；容器里的 `127.0.0.1` 指容器本身，代理应填容器可访问的宿主机地址。

## 已实现

- SQLite 持久队列、同编号活动任务去重、单 worker 顺序执行、启动后将中断任务重新入队。
- 普通编号和 FC2 编号分别按已启用的适用来源执行；严格核对返回编号，不采用模糊搜索首条结果。
- 按固定来源顺序填补空字段，保留来源原始快照与字段来源，成功资料进入现有字段锁、分类和同步流程。
- 任务取消会阻止正在抓取的结果落库；当前 HTTP 请求最多等超时结束，不保证立即中断网络请求。
- 资料成功与图片下载分开处理；封面和海报写入应用缓存，不写原视频目录。原有同步按钮可补抓失败图片。
- 现有自动任务限额与失败退避继续生效；不移动、重命名或删除原视频。

## 验证与限制

2026-11-02：合成页面覆盖三个解析器；临时数据库覆盖去重、取消、恢复、失败结果；片库接入测试验证手工锁和自动标签，并校验源文件字节与修改时间不变。两条已有匹配编号经用户配置的本地 HTTP 代理实测，均由 JavBus 匹配成功；Jav321 返回未找到。另一次真实封面请求验证下载成功（JPEG，171138 字节），并验证无效图片响应不会覆盖已有缓存。这不是全来源、全编号或全平台验收，FC2 尚未进行真实来源验收。

已追加 [来源开关、字段优先级、来源诊断和媒体库管理](NETWORK-AND-LIBRARIES.md)。仍需补齐站点级缓存复用、站点限流策略、完整图片任务、其他采集器和更完整的编号类型路由。遇到站点验证页会报告失败，不绕过访问验证。

内置引擎数据库为 `data/builtin-scraper.db`，包含任务、原始资料和图片 URL，属于私人运行资料，已被 Git 忽略。现有应用备份仍只覆盖主片库与配置；需要完整迁移内置队列时，先停止应用，再整体备份 data 目录。不要在内置任务运行中恢复应用备份。

当前暂不提供内部任务库与主片库的原子备份恢复。内置资料同步写入的主片库内容仍随现有备份保留，内部任务历史需整体备份 data 才能保留。

站点设置、来源缓存、独立剧照队列和详情画廊见 [独立刮削与剧照](INDEPENDENT-SCRAPING.md)。
