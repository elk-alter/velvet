# 文件质量与待处理 · 首版

入口：片库顶部“待处理”，或“媒体库 → 待处理与质量”。影片详情“当前文件 · 质量与更新”操作的是选中的具体文件，其他分段和版本不随之标记。

## 使用流程

1. 设目标画质（默认 1080p，也可不限/720p/4K）；低于目标的已知画质文件进入待更新。未知尺寸不会被当成低画质。
2. 按问题筛选并选择文件；检查、标记明显水印/人工损坏/需要更新，或填写备注。水印首版由人工确认。
3. 接受现状或忽略后退出“需要更新”筛选，原始问题保留；可恢复待处理，也可分别撤销人工标记。批量动作最多 500 个文件，资料刮削沿用 50 个限制。
4. 新文件导入后先扫描；同片有更高分辨率版本时仅提示候选，需对比内容、画质和分段完整性。不会自行替换文件。

目标是个人要求，不是最高发行版本证明。更高分辨率不保证视觉更好；4K 徽标只表示尺寸，不再叫“精品”。不会因文件名标有 4K 就判定真实 4K。外部版本监测、OCR 水印判断、放大编码识别仍待开发。

## 三种检查

|范围|实际工作|结论边界|
|---|---|---|
|快速探测|ffprobe 容器和轨道|不代表全片正常|
|抽样解码|开头/中间/结尾各最多15秒|短片位置可能重叠；未抽到的区间仍可能有问题|
|完整解码|首视频轨和首音轨解码到空输出|不检查所有附加轨，也不证明无水印/黑屏或视觉质量合格|

检查只读，不生成转码文件。单工作线程降低磁盘争用；完整检查可能耗时很长，默认不全库自动启动。当前上限为单次探测45秒、单段抽样180秒、全片6小时；超时报不确定，不报通过。文件离线/权限、工具缺失、探测错误、解码错误分别处理，解码异常只标“疑似损坏”。日志能显示首个报错/抽样起点，尚无逐帧错误定位。

任务保存于主片库 file_reviews。重启将进行中的检查重新排队，支持取消与继续。重启续查从该文件重新开始，不从中断帧续跑。复查过程中仍需等待当前子进程结束/终止；仅管理自己启动的检查子进程。

按扫描记录的大小/修改时间识别文件版本；重新扫描发现变化后，标记和检查结论进入过期状态，需重新审阅。检查中也核对变化。对保留大小及时间戳的外部修改没有内容指纹保证。

## 资料审阅

工作台提供待匹配、缺字段、缺缓存封面、处理错误筛选；错误摘要还参考任务中心最近100项任务。可批量刮削，编号纠正在详情的既有编辑区完成。缺封面按应用缓存判断，不等于外部一定存在封面；完整候选匹配/置信度审阅尚待开发。

## 悬停截图

桌面停留600毫秒后读取已存在本地截图，约1.1秒切换一张；固定画幅，移开恢复封面，不在悬停时运行截图或读取原视频。只预览当前悬停卡片；选中卡片、移动到选择框、触摸及系统减少动态效果时停用。顶部可关闭，偏好保存在浏览器。没有截图则保留封面。

## 备份与后续

标记、目标与检查记录在主片库内，随主库备份恢复；恢复入口会检查文件检查线程锁。已用合成视频验证三类检查、截断文件、标记恢复及源文件 SHA-256 不变。现有主库备份仍不覆盖独立来源缓存和图片，全量目录恢复/统一任务编排仍是 P0。

首版不等于全部 P0 完成：后续补统一扫描/文字/图片/检查任务对账、候选匹配工作台、来源退避治理、结构化脱敏诊断和完整升级/灾难恢复。
