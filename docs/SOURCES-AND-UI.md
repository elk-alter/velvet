# 来源目录与管理页面

## 两种执行方式

来源目录以已核对的 Amane 0.24.1 源码基线登记 24 项影片来源。它不是“24 个来源均已原生移植”的声明。

| 方式 | 范围 | 依赖 |
|---|---|---|
| Velvet 内置 | JavBus、Jav321、FC2、FC2Club、FC2PPVDB、Freejavbt、Airav、XCity，共 8 项 | requirements.txt、对应站点网络；不依赖 Amane 进程 |
| Amane 完整引擎 | 使用配置的 Amane 实例的分类路线、字段择优、缓存、站点凭据、浏览器后端及已安装插件 | Amane 必须运行，地址和 Token 正确，站点自身条件满足 |

“刮削来源”页面显示来源执行方式、当前模式下是否启用，以及从 Amane 实时读取的分类路线。路线里出现的新插件 ID 也会加入目录；静态来源 URL 来自固定源码版本，不保证与未来版本一致。目录可在 Amane 离线时继续显示内置来源。

2026-11-02 本机实例报告版本 0.24.1，读取到 7 类路线和 13 个路线内启用来源。此处的“启用”表示配置，不代表网络检测通过或任意编号都能匹配。测试完整引擎的检测接口时，JavBus/JavDB 返回网络异常，DMM 返回地区限制，未将它们报告为可用。

## 使用

1. 打开“刮削来源”，查看当前引擎、来源目录和本机连接状态。
2. 使用独立内置模式时，进入“配置内置来源”，勾选来源，用上下按钮调整顺序，通过字段下拉框设置首选来源，再保存。
3. 希望使用本机全部配置路线时，点击“使用本机 Amane 完整来源”。它使用已有的外部服务连接配置；有进行中的任务时会拒绝切换，避免把旧引擎任务 ID 交给新引擎。
4. 完整模式保留 Amane 的路线和凭据；这批不代用户修改 Amane 配置。需要修改完整路线时在 Amane 设置中完成，然后刷新 Velvet 的本机配置。
5. 在“网络检测”查看逐来源结果。完整模式会调用该实例的真实检测接口，使用该实例的网络设置；Velvet 内置代理不会自动写入 Amane。

新增安装的默认内置清单包含 8 项；已有显式来源选择保持原样。按编号选择适用路线，不会为每个编号请求所有来源。默认内置普通路线支持 JavBus/Jav321/Freejavbt/Airav/XCity；FC2 路线支持 FC2/FC2Club/FC2PPVDB/Freejavbt/Airav。额外来源的合成页面解析已验证，尚未做全部来源的真实编号验收。

## 页面形式

参考 Amane 的管理信息架构，将媒体库、刮削来源、网络检测和任务改为独立管理页面。沿用 Velvet 的明暗配色，提供固定页头、独立返回按钮、管理分区导航、统计卡和来源/任务表格。任务页按状态筛选最近 100 条记录，支持自动刮削开关、取消、重新刮削和同步资料图片。

保留原片库的筛选和滚动状态；“返回片库”退出管理页。较短的资料编辑仍使用现有详情窗口。管理页面不复制 Amane 品牌、图标或截图素材，源码移植声明见 NOTICE。

来源盘点只输出版本、来源标识与公开 URL、路线和启用状态，不返回原始配置、Cookie、API Key 或代理凭据。向配置的 Amane 服务执行鉴权请求仍使用其既有 Token；此处不是声称程序从不读取鉴权凭据。

## 验证范围

新增测试覆盖五个采集器解析、编号身份、完整来源目录、离线降级、来源配置脱敏，以及完整引擎网络结果的保留。浏览器使用隔离的合成数据检查来源总览、内置来源配置及固定页头。预览中的计数与路线是合成数据，未包含真实片库内容。

主服务需要重启才能加载新后端和资源路由。本批未切换用户正在运行的引擎或修改本机 Amane 网络配置，也未触碰原视频。
