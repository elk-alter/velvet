# 部署：本地优先，NAS 实验性

主要使用路径是 Windows + Python + 本地浏览器。macOS/Linux 的原生目录选择与播放器分支未完成全面实机验证。

## Docker / NAS

要求目标设备支持 Docker Compose；仓库不提供已发布容器镜像。

1. 复制 `.env.example` 为 `.env`。
2. 填写至少 12 位的 `VELVET_PASSWORD` 与 NAS 上实际 `MEDIA_PATH`。
3. 执行 `docker compose up -d --build`。
4. 访问 `http://NAS局域网IP:8765`，在网页中导入容器路径 `/media`。

媒体以只读方式挂载，应用资料保存在 `./data`。NAS 模式不调用服务器的桌面播放器。浏览器不能解码时需通过共享目录使用电脑播放器；没有实时转码。

此配置尚未验证具体 NAS 品牌、ARM64/AMD64、设备权限和硬件加速。HTTP Basic 不提供传输加密，只适合可信局域网试验；跨网络访问应使用 VPN 或正确配置的 HTTPS 反向代理，不要把实验服务直接暴露公网。

## 备份与升级

升级前停止后台任务并做备份。保存 `data/`，其中可能含私人资料和凭证，不进入源码仓库。保留旧程序和备份作为回滚依据。媒体路径映射、跨系统迁移和备份恢复需在测试目录先演练。
