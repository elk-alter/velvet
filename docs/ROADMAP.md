# 迭代路线图

alpha.13 集中改善日常操作、播放和资料恢复。范围见 [alpha.13 需求](ALPHA13-REQUIREMENTS.md)，实际进度见 [交付台账](DELIVERY-STATUS.md)。历史体验问题见 [U01–U40](UX-AUDIT.md)，已有能力见 [功能清单](FEATURES.md)。

## 接下来怎么更新

| 版本 | 最重要的改动 | 完成标志 |
|---|---|---|
| **alpha.11 界面统一** | 统一片库、详情、演员、分类、合集、刮削、硬盘与设置的视觉基础、标题和操作区。 | 桌面与 390px、亮暗主题、键盘及隐私场景通过；详情、翻页和已有数据通过回归。 |
| **alpha.12 常用操作顺畅** | 优化筛选与选择、详情返回与连续浏览、待处理到修正、硬盘盘点到计划的路径。 | 四条完整流程能从原位置就近完成，返回时保留有效筛选、页码和位置；后台刷新后仍能打开详情。 |
| **alpha.13 常用操作与播放** | 统一关闭和返回、应用内目录浏览、集中筛选、在位播放与按原因处理资料。 | 桌面和 390px 走通浏览、选择、返回和重试，保持既有性能预算。 |
| **alpha.14 NAS 与跨端** | 容器部署、服务端路径、权限与认证、浏览器访问和跨设备验证。 | 在一台实际目标 NAS 上走通安装、导入、浏览、播放、升级、备份及恢复，并记录设备型号与验证范围。 |
| **alpha.15 硬盘整理体验** | 简化多盘盘点、规划、冲突处理及恢复操作，覆盖可取得的可移动介质。 | 从盘点到整理、校验和撤销可连续完成，恢复前能核对设备、目录与文件变更。 |
| **beta.1 安装和维护** | Windows 安装与升级、缓存容量及清理、故障恢复与自动化发布门禁。 | Windows 新装与旧库升级可独立完成，失败可回滚，测试、版本、附件和校验对应同一提交。 |

原排期将 NAS 放在 alpha.11。现优先改善当前每天使用的 Windows 界面，NAS 功能集中到 alpha.14。设备提前具备时可并行完成部署预研。alpha.11 有完整验收项，后续版本按各自主线逐次细化，发布窗口随验收结果确定。

## alpha.5：可靠性与目录政策闭环

**[完整需求及验收：A5-01–A5-32](ALPHA5-REQUIREMENTS.md)**。

统一任务/重启对账、安全启停、等待诊断、人工合集规则、目录排除一致性、完整数据备份路径和迁移演练、性能基线、端到端回归。

新增 [E-ORG 原始媒体整理Epic](EPIC-RAW-MEDIA-ORGANIZATION.md)：alpha.5先交付多盘盘点和只读整理预览；安全复制条件试点，实际移动后续评审。

U03本版先做基线和明确止损，完整服务端查询改造后续专项推进；不承诺一次完成所有大库优化。交付实现与证据见[开发进度](ALPHA5-PROGRESS.md)和[验收记录](ALPHA5-VALIDATION.md)，复制条件试点延期。

## alpha.6 基础交付

独立硬盘工作区、多盘快照与查询、固定计划、安全复制和同盘移动、校验绑定、同挂载路径下恢复及撤销。主片库使用服务端分页并按需读取详情。首发以 Windows NTFS 合成资料及实际文件操作验收。见 [首发范围](ALPHA6-REQUIREMENTS.md) 与 [版本说明](RELEASE-0.1.0-alpha.6.md)。

## alpha.7 性能、功能与界面完善

[完整需求与验收 A7-01–16](ALPHA7-REQUIREMENTS.md)。以 alpha.6 为基线，先量化大库冷首屏、新筛选、图片与后台并发，再改善列表、卡片、详情和管理导航。保留索引的冷启动目标为 1 秒，首次建索引争取同一目标，等待达到 1 秒时显示真实进度。补齐换盘符后的安全续跑、批量刮削失败处理和问题级质量审阅。

真实拔盘、exFAT 与多分区列为设备可用后验证；先在 NTFS 合成媒体上验收任务恢复。标签和人物治理、合集选图等按 P1 排期。

## alpha.8 日常使用稳定版

[A8-01–06](ALPHA8-REQUIREMENTS.md) 为必达。先收口发布后修补、运行与缺失状态，再统一识别、刮削失败、类别和评分，最后完成桌面/窄屏交互、性能、迁移和发布验收。源码提交、发布与本机部署分别记录。

## alpha.9 硬盘统一管理完善

实施需求与验收条件见 [A9-01–05](ALPHA9-REQUIREMENTS.md)。

贯通盘点、计划、执行、校验、入库和撤销，完善多来源选择、容量和冲突提示、离线状态及恢复流程。以独立合成多盘场景完成中断、续跑与撤销闭环。承接 E-ORG 未验收项及 A7-10 可用设备验证。

## alpha.10 标签、人物和浏览治理

[A10-01–05](ALPHA10-REQUIREMENTS.md) 承接 A7-08、A7-09、A7-15。提供可视化标签规则、影响预览和撤销，演员别名合并、同名处理及偏好迁移，保存筛选、合集选图和演员/分类分页。变更前可预览，变更后可撤销，作品与偏好保持可核对。

## alpha.11 界面统一

[A11-01–06](ALPHA11-REQUIREMENTS.md) 按公共视觉基础、样板页、全站推广和回归验收推进。固定详情标题与独立关闭控件，统一片库、演员库、分类、合集和管理页的组件与视觉层级。保持现有业务状态和数据兼容性。

## alpha.12 常用操作顺畅

实施范围与验收见 [A12-01–06](ALPHA12-REQUIREMENTS.md)。

- **找片。** 统一常用筛选、展开的多选标签、筛选预设和分页。选择范围和命中原因可见。查看详情或合集后恢复原浏览位置。
- **看详情。** 将标题、剧照、版本、分集、播放和编辑按使用顺序布置。快速切卡或后台更新时维持正确详情，保留手工编辑和隐私遮盖。
- **补资料。** 待处理条目可直接前往改编号、补封面或查看失败原因，返回时保留任务范围和筛选。已有成功资料和字段锁受保护。
- **管硬盘。** 从盘点到比对、计划、已入库和撤销使用一致的文件范围提示。用户能看懂设备离线、目标冲突和等待校验的下一步。

沿用 alpha.11 性能基线。首次建索引首屏中位数恢复至 ≤3.5 秒，等待达到 1 秒前显示真实阶段进度。P1 候选包括观看历史入口和更紧凑的浏览密度。

## alpha.13 常用操作与播放

关闭与返回统一到各自固定位置。硬盘登记可浏览、粘贴与核对身份。筛选支持先编辑再统一应用。详情内播放，按实际能力呈现字幕、音轨和回退入口。待处理区分原因并确认可重试范围。详见 [A13-01–06](ALPHA13-REQUIREMENTS.md)。

## alpha.14 NAS 与跨端基础

选定实际 NAS 环境后验证容器安装、升级、认证、服务端路径映射、权限诊断、局域网访问、移动端布局和播放回退。平台覆盖按实测记录。

## alpha.15 硬盘整理体验

贯通多盘盘点、规则预览、执行、校验、入库与撤销，合并需要来回切换的设备和冲突核对。按可获得的设备验收拔盘、换盘符、exFAT 和多分区，延续 A7-10。

## beta.1 安装和长期维护

提供 Windows 安装/升级入口、运行诊断、缓存容量与清理、受控回滚和实际启用的 CI 门禁。验证全新安装、旧数据升级和回滚，构建与测试对应同一提交。

## 独立实验与设备验证

片单首页、按需转码和画面语义识别保留为独立候选。画面识别先定义本地模型、样本、误报指标和资源预算。采用产品目标与实测条件决定是否纳入某个版本。真实拔盘、换盘符、exFAT 和多分区继续按设备覆盖记入台账。

上述是交付顺序而非日期承诺。日常浏览/扫描及开发测试保持原媒体只读；alpha.6执行仅限用户明确确认的具体计划，不以入口存在代替验收。
