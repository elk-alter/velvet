# ADR 0005：复制后单独批准的可恢复源归档

日期：2026-11-05。状态：alpha.6开发候选。关联A6-06、08、10–11、15–19、28。

## 决定

完成copy任务不移动或删除源。只有copy全批完成并绑定后，用户从任务另开archive-preview，审阅固定归档草稿并通过archive-approve独立确认。普通approve不能批准归档草稿，也不能绕过反向计划的专用确认。

每项冻结保留副本的设备、文件身份、完整SHA-256/大小/时间、归属本次复制的绑定及资产/默认播放身份。预览、批准和每个移动校验边界复检副本；同内容外部替换不认领。源仍作为当前默认位置时先要求切换有效副本。明确归属的伴随资源同样校验，共享资源沿用保留清单。

源移入原盘点根/.velvet-archive/原copy任务ID/原相对路径。namespace为应用保留；已有同名根无归属记录拒绝。organization_archive_plans保存原copy→固定草稿→归档任务关系；organization_archive_roots在排队之前保留根和设备身份。预览不创建物理目录，批准后的保留根即使任务取消也继续保护。它不是用户可随意取消的排除项。恢复后再次归档采用最近成功反向任务ID区别批准摘要。

archive复用同设备MoveExecutor的全批暂存/不覆盖提交/稳定身份绑定/持久日志/控制与租约。副本校验器在archive运行时必需，暂存/提交/绑定之间副本变化即停并保留隔离现场；不能使用取消来释放未对账物理变更。没有删除源文件或跨盘rename的降级路径。

## 扫描、播放与恢复

归档根合并进强制排除，扫描/盘点跳过保留namespace，旧索引及查询不默认展示归档文件。媒体库/盘点不能新登记归档目录。位置DTO标记archived，不能直接prefer为默认播放；copy解绑也不能自动选归档位置作为替代。需要使用归档源时先按任务恢复。默认目标副本、video_id、UUID、人工资料和关系依据保持。

反向计划根据源归属的卷、文件身份和完整内容定位已归档/暂存文件，不要求保留副本继续健康；它可能正是需要救回的唯一好文件。恢复仍需重新确认，不覆盖被外部文件占据的原路径。恢复不修复外部损坏的副本，也不凭空宣称其可播放。归档根记录不会因恢复后为空而自动取消，防止旧内容被后台重新导入。

## 设备边界

当前仅开放可写、稳定卷身份的Windows NTFS/ReFS策略；本批实际执行测试为Windows NTFS合成文件，未实测ReFS。未知/只读/FAT32/exFAT及非Windows设备禁用归档并解释原因，复制保源仍可用。不从文件系统名称推导所有NAS安全能力。exFAT实盘仍缺设备，不能用策略拒绝测试代替A6-27。后续平台需先证明不覆盖移动和可靠恢复，再扩展策略。

## 代价与验收

副本反复完整校验偏向正确性，大文件归档可能耗时，不能把它称作已达大批量/性能目标。现有数据库恢复门禁继续保守，不替代物理操作日志对账。完整平台、故障、迁移和运行交付另见[alpha.6进度](../ALPHA6-PROGRESS.md)。
