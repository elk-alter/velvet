# 0012 · 登记目录身份与可审阅重连

日期：2026-11-05。状态：采纳（登记及盘点位置重连部分）。关联：A6-01–04/15/27/28。

## 问题与决定

卷身份相同不能说明目录相同。旧remap只校验卷，新版硬盘页又没有重连接口；同一卷上替换一个目录可能被旧快照当作在线原目录。

新增storage_root_proofs(device_id,identity,file_id,root,recorded)，独立于storage_devices原六列。新登记记录卷标识及目录st_ino字符串，避免大整数存储溢出；同卷各根分别记录，不把物理卷当作盘点位置。旧库迁移只建表，不根据当前文件系统编造过去的证明。无记录或文件系统不提供非零标识时，界面说明需人工核对。

Python在Windows可用时以st_ino提供文件索引，见[Python 3.10文档](https://docs.python.org/3.10/library/os.html#os.stat_result)。微软说明同卷文件索引可帮助判定同一对象，NTFS对象删除前保持ID，删除后可能重用；见[GetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfileinformationbyhandle)及[BY_HANDLE_FILE_INFORMATION](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-by_handle_file_information)。因此这是有边界的目录证据，不能宣称永久/密码学身份、全文件系统认证或替代文件完整哈希。

## 重连契约

独立页面先给出旧位置与状态，再选择候选目录。服务端只读核对非链接目录、归档隔离、卷身份和已记录目录标识；稳定卷的目录标识不符即拒绝，即使文件内容和属性相同。不合并另一个已登记的同一目录，不在盘点运行中改挂载。

预览摘要包含登记记录、旧证明、候选规范路径/身份/目录标识及最新盘点状态。确认需Token、confirmed:true和当前digest，BEGIN IMMEDIATE内再次核对；旧登记缺少证明或卷身份不稳定须另行manual_confirmed:true。保留device_id、快照、人工建议及保留偏好，仅更新盘点位置与当前目录证据，不搬文件。

当同一路径接入另一卷或换了目录，默认登记拒绝覆盖旧登记。用户明确new_location:true才允许另建ID；若当前对象已有匹配登记则复用，防止重复点击新建。旧记录与快照保留，并按实际卷/目录身份显示离线或身份变化，不把旧记录重新绑定到新对象。

## 读、盘点与规划消费者

设备列表逐项区分离线、卷变化、目录变化、权限不足、链接和其它访问错误；单项异常不使整页失败。新查询复用这些在线状态，旧范围变化沿原409机制失效。物理详情另显示directory_changed，不把同属性的替换文件标成原快照当前文件。规划和完整准备复用verify_root。

盘点在开始、目录遍历、文件资料读取后/提交前及结束核对卷与根标识；识别变化时中断，不将混合设备数据发布为新完成/部分快照。原完整快照不因此视为删除。权限/盘点错误的更广泛增量合并语义仍分别验收。

## 尚未完成的关联范围

本决定不改写已批准任务payload、稳定资产关系路径、videos.path或文件操作日志。盘符/挂载变化后，已批准任务及移动暂存/已提交副本的有效路径解析、人工核对和继续恢复仍须完成；当前不能据登记重连把A6-03/15整项标通过。不得以要求用户重新规划代替该必达恢复能力。

真实拔盘、盘符切换、exFAT及多分区硬件仍需各自证据。当前实际NTFS目录改名及模拟卷替换只证明相应分支，不冒充硬件验收。数据库恢复继续遵守ADR0009，不因修改挂载元数据绕过物理日志对账。
