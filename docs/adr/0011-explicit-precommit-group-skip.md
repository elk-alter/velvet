# 0011 · 明确跳过尚未提交的文件组

日期：2026-11-05。状态：采纳。关联：A6-13/14/19/30。

## 问题

失败项只能继续重试，不能记录用户决定跳过。直接把步骤改成done会伪造校验和绑定成功；从批准清单删除条目会改写原授权。单独跳过视频或字幕还可能留下不一致的关联。

## 决定

保留不可变payload和approval_digest，保留步骤原执行checkpoint。在organization_steps.details中追加skip:{confirmed_at,group_ordinal}，并记录skipped步骤事件；不建立新任务、队列、表或执行状态。旧记录无此字段，解释为未跳过。跳过是取消该组后续执行的明确决定，不扩大操作授权，不做文件写入。

使用稳定asset_id/parent_asset_id，把视频及明确归属的伴随资源一起审阅。预览摘要绑定任务、批准摘要、任务状态及更新时间、全部组成员和当前checkpoint/details。确认须再次在BEGIN IMMEDIATE内核对；过期拒绝，不能套用到新状态。

仅已停止任务可审阅：failed/partial/interrupted/cancelled，或已暂停的waiting。queued/running、未暂停的waiting、维护中的任务均拒绝。已有撤销计划、归档和撤销任务不提供跳过。copy仅允许pending/copying/verified；move和keep仅允许pending。组内任一成员已暂存移动、提交、进入绑定或完成，则整组拒绝，不清理现场或释放应保留的对账保护。

执行器领取后重读任务，再跳过已决定的组，避免初读与claim之间的决定被旧副本覆盖。移动只对剩余成员暂存/发布和事务绑定；循环改名依赖若被跳过源占住，原冲突检查仍会拒绝覆盖。反向计划不包含明确跳过的原位文件。

## 完成与恢复语义

processed只计实际done，skipped单独计数，原总数不减。没有跳过才允许整批done。有跳过且全部条目已done或skip时，以既有cancelled结束，界面与历史显示“已结束 · 含跳过”；其它错误仍是failed/partial，须明确继续。全部已处理或跳过后拒绝resume，避免把用户的跳过决定重新激活；若要整理跳过文件，制定新计划。

原执行checkpoint保留，复制字节/校验/提交仍按实际阶段推导。未提交的复制暂存继续保留，清理须走已有所有权、完整摘要、句柄及明确确认；verified暂存也纳入安全清理。清理将步骤回pending时保留skip决定。任何已提交目标、源媒体和移动暂存都不因跳过被删除。

主库及完整备份沿用details JSON保存决定。恢复不新增隐式重跑；物理历史仍须按ADR0009核对。不会借跳过把needs_binding或移动暂存变成可直接恢复的安全状态。
