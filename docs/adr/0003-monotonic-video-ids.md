# ADR 0003：数字视频ID在移除和恢复后不复用

日期：2026-11-05。状态：采纳并实现为alpha.6开发候选。关联A6-17、19、28–29，补充[ADR0002](0002-alpha6-file-identity-and-execution.md)。

## 问题与边界

稳定asset UUID已与位置分开，但旧封面/截图、OCR、质量、部分偏好及队列仍使用数字video_id。旧videos.id为INTEGER PRIMARY KEY，移除最大ID后普通INSERT会复用它；相同大小/时间还可能让旧质量记录看似有效。合成回归已复现。仅有asset UUID并不能保护这些旧消费者。

## 决定

videos.id采用SQLite AUTOINCREMENT，既有ID和外部引用不变。迁移在独立事务中重建旧表，保留原DDL的其它字段/约束、显式索引、触发器及视图引用；复制原ID/字段，重建失败整体回滚。外键检查与迁移前比较，不引入新悬空引用，也不擅自清理既有孤立记录。仅迁移期间关闭本连接外键并启用legacy_alter_table，结束恢复原PRAGMA。

分配水位取当前ID、sqlite_sequence、已知旧引用（含关系撤销、重复偏好历史及整理计划中的本地ID）与应用缓存中的有效数字ID最大值；只读取数据目录图片命名及analysis第一层编号，不读取/整理媒体盘。空表、最大记录移除、重复迁移及序列有空洞时仍保留水位。UPSERT可消耗序列产生空洞，调用方不得依赖连续ID。

没有采用只修改各INSERT调用的分配器：旧模块及导入路径可能遗漏；数据库级自动分配覆盖扫描和原文件绑定。也不在首次迁移重编号或批量删除旧图片/质量记录，以免丢失现有身份与人工结果。直接手写SQL强行指定旧ID不属于自动分配保证。

## 恢复

主库及离线完整恢复先记录当前水位，再在已校验的暂存数据库上迁移并至少推进到当前水位。成功后才替换当前数据库/目录；准备失败不改变当前库，保留既有回滚快照。离线恢复返回id_watermark，归档校验和验证的是原归档；恢复后的数据库可能因本次迁移/序列推进而不同。

它只解决数字ID分配回退，不替代文件日志对账；未完成或已有物理整理历史的恢复仍由restore_safety保守拒绝。完整alpha.5升级、物理回退和旧程序演练尚未验收。对于迁移前已经错误挂接、且没有来源证据的旧缓存，不凭猜测修复或宣称已恢复正确内容。

## 验证

合成测试覆盖最大ID移除后新增不继承封面/质量、额外BLOB字段/视图/触发器/外键/UUID保留、索引重建失败原子回滚、空表序列、旧引用及图片/OCR水位、缓存不可读时无半迁移、主库/完整恢复保持水位、恢复准备失败不替换当前数据。没有执行真实媒体文件操作。完整发行/设备/迁移验收仍见[alpha.6进度](../ALPHA6-PROGRESS.md)。
