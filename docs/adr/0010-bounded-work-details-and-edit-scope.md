# ADR0010：单作品分页读取与明确的编辑范围

日期：2026-11-05。状态：采纳。关联A6-20–25、29；不表示这些需求整体验收完成。

## 问题

按作品读取仍可能一次呈现数万个版本/分段。原详情缓存和关系编辑共用完整作品模型，简单截断会使页面把已加载部分当作全部，破坏续播、默认版本、质量比较或批量修改范围。

## 决定

MovieDetails复用已刷新的SQL读模型，分开返回当前完整文件、作品计数、版本摘要页、当前版本分段页及当前/默认版本摘要。默认10版本/20分段，上限20/50；当前文件可不在正在浏览的页内，仍单独保留。窗口外的版本不呈现完整文件资料，不调用全作品hierarchy。分段按人工顺序和唯一文件ID稳定排序；默认/续播及版本质量排序沿用原规则，包括最后的首次出现次序。

跨页“下一段”从后端单独定位，不从当前页数组猜测；相邻分段缺失时仍按原行为停止，不悄悄跳过。质量比较的索引中无缺失分段的最高画质版本由完整SQL范围产生，不能因为高版本未加载而遗漏候选。

版本选择器固定保留当前和默认版本，页码只计该页摘要；固定项会注明。翻页只换导航，不重新初始化编辑区。实际切换文件/版本才调用已有未保存确认；页码和焦点保留，关闭/换页后的迟到响应通过请求代数、取消信号和视图代数拒绝。

## 一致性与恢复

详情revision由读取实例代数和SQL源revision组成，客户端只原样回传。资料、规则、偏好等变化拒绝旧页；重启或HTTP恢复重建MovieDetails实例，即使SQLite计数相同也拒绝旧页。它不是执行批准或文件所有权证明，没有持久业务表、租约或新队列。

兼容测试发现NULL画质/观看/缺失/进度等会被SQL聚合忽略，与原Python默认版本及续播不一致。聚合和窗口以原逻辑的零值解释NULL，原视频/人工字段不改写。browse_state.projection_schema升至2：schema1只使聚合和查询失效，复用现有逐文件投影；schema0/未知格式仍重建投影。回滚执行仍遵守ADR0009，不靠删租约或历史放行。

## 关系编辑与兼容

后续性能调整（第二十六批）：聚合投影schema3预计算版本最大可见mtime及该时间的最小文件ID。详情仍按原质量/保留偏好/最大时间/首次出现顺序排序，首选与续播规则不变；不再每次对每个候选版本做两个关联子查询。从schema1/2升级仅使聚合失效，复用逐文件投影，保留原rebuild要求；未知格式仍重建。不增加业务身份或可执行计划字段。

保留旧movie响应供兼容；新主详情使用分页接口。关系编辑可附max_files≤100，后端在应用数据库互斥范围内先核对全部索引成员，再呈现完整作品；计数包含被排除的成员，防止可见页很小却加载巨大隐藏图。跨页选择超过范围时拒绝，不缩小用户选择。

大型作品的单文件关系入口明确标出“本次仅编辑当前文件”，表单与提交只含当前文件ID。小作品继续编辑完整范围。不能把当前分段页当作整部作品保存。旧无上限兼容接口及其它旧管理全量消费者仍是待迁移项，不据此声称所有入口均有界。

## 证据和限制

后端、HTTP、Node客户端、旧数据NULL及schema1迁移回归；合成24版本/1560文件浏览器验证续播、版本/分段页、未保存编辑、默认版、键盘、隐私、390px。单文件关系保存后仅1条变化，其余1559条不变，资料变化后旧页拒绝。压力脚本独立覆盖1万/5万单作品的分段与版本，列明索引准备、HTTP、返回大小、呈现数量和峰值内存。

不替代浏览器首次绘制、所有旧导航/关闭入口、实际视频解码/自动续播、设备故障或最终发行验收。A6-22冷性能及其它P0继续跟踪，不能只凭本模块或测试数量发布。
