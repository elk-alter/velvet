# ADR0009：数据库恢复前核对物理日志并保留证据

日期：2026-11-05。状态：采纳，完整升级/故障矩阵仍在验收。关联A6-16、19、28–29。

## 问题

备份不包含原视频，数据库恢复不能撤销物理移动。原门禁拒绝所有非pending步骤，连只做索引关联的keep、已经反向恢复的移动，也永久阻止恢复。直接清日志或接受浏览器的“已对账”布尔值会丢失文件归属证据。

## 决定

restore_reconciliation负责只读对账；restore_safety仍为最终门禁。keep/unbind_copy只在清单摘要、完整步骤、无暂存且任务终止状态兼容时允许普通恢复。物理操作必须先生成固定对账计划，再在恢复独占范围内重新计算，不能传入一个信任标记跳过检查。

将当前与备份的不可变批准清单合并，以设备身份和文件身份追踪copy创建对象及move/archive位置链，包含已完成的反向任务。涉及应用写入的文件必须在线，完整指纹和设备/文件身份匹配；恢复所需位置必须与实际位置一致。恢复旧快照前通常须通过原任务的独立确认撤销移动。恢复同一个移动后的快照无需无谓地先撤销。只读复制输入不是被应用改动的对象，不声称本次重新校验了它；已发布复制目标即使在旧快照中不存在，也须验证并列明保留。

活跃任务、遗留暂存、未完成提交/绑定、冲突历史、不可证明身份或内容变化都拒绝，不自动修复或删除。已完成反向可解释原任务的中间位置，但不抹除原步骤。外部同内容替换文件仍因身份不同而拒绝。

计划摘要绑定备份归档字节、当前配置和两端权威数据库签名、文件证明及日志。数据库签名包含未知表/BLOB/WITHOUT ROWID及相关索引、视图、触发器；已知查询缓存和运行租约等派生表不入签名。资料、归档或文件变化必须重新预览。全量哈希有成本，不是瞬时按钮；外部程序仍可能在核对后改动文件，因此不将它表述为跨进程文件锁。

## 证据与恢复边界

恢复前主库生成before-restore备份，完整恢复保留原data.before目录；均保留完整旧库。另存私有restore-audits回执，记录本次两端任务、步骤、反向关系、证明及回滚位置。完整备份/恢复携带旧回执，不因再次恢复较旧快照而抹掉链条。回执不等于整理任务表，也不会被执行器自动重放。主库恢复继续保留当前目录中的历史回执。

restore-plans及restore-audits位于私有数据目录，包含路径和资料，不提交、不作为公开发行附件。HTTP只返回数量、最多50个保留文件/问题和计划令牌，不返回完整批准清单、指纹或日志。实际恢复再次校验服务端保存的计划；数字ID水位继续保留。离线完整对账要求已有Velvet数据库；无库恢复遇到物理日志仍保守拒绝，灾难恢复矩阵未因此宣布完成。

## 验证及限制

独立NTFS合成文件覆盖keep、复制、移动后/移动前快照、反向、六个移动检查点、资料变化/归档替换/同内容新文件身份、私有日志留存及完整恢复。HTTP覆盖鉴权、名称确认、伪造布尔值、过期计划和成功恢复。网页验证阻止不匹配位置、撤销后保留副本说明、键盘确认及390px视口；旧alpha.5提交演练重复迁移、复制/移动/反向、对账恢复、旧程序读取。

这些不是所有故障、全部人工资料/图片/OCR及队列生命周期、真实拔盘/exFAT或灾难恢复的完整验收。不得通过清理日志、删除租约或扩大只读承诺来补齐验收。
