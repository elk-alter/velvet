# ADR0007：文件范围租约与持久写入排队

日期：2026-11-05。状态：采纳（分阶段接入）。关联：A6-13–16、ORG-34。

## 问题与决定

原全工作区读/写互斥让整理任意文件阻止无关文件播放，连续读队列又可能延迟写任务。保留兼容的resource_claims四列，新增resource_scopes及resource_waiters；没有范围的旧租约按全局处理。路径统一规范化，目录范围覆盖其后代，文件/资产UUID/视频ID是独立资源；整理另带设备令牌，设备上的写任务仍串行。不能将设备串行理解为全部设备已并行验收。

在同一个IMMEDIATE事务内登记稳定owner的写入票号、检查活动租约和较早的冲突票号、领取范围及删除自己的票号。领取失败也提交票号，新冲突读者不可插队，无关范围可以通过。不等待持有网络/媒体进程的数据库事务；只在文件安全边界释放读租约，不中断正在检查的文件。暂停/取消删除等待票号，运行租约仍由执行器释放。

整理范围取固定批准清单，不能依赖排队期间变化的video_id映射。原始文件后来进入片库时，读取者同时持资产UUID租约，避免身份物化改变等待范围。未完成操作的reconcile范围持久保留，只有对应原任务/批准反向任务可豁免；不能因暂停或无进程而按超时清除。

## 接入及限制

播放、按库根扫描、逐文件质量检查、逐作品图片、独立刮削缓存已接范围；整理队列可以跳过被阻塞的头任务尝试不同设备任务。任务仍单执行线程，设备公平性与细粒度覆盖未整体验收。部分同步/重复检查/通用HTTP/整理预览/残片清理及撤销维护仍保守使用全局租约。备份恢复仍全局独占，原文件历史对账门禁保持。

## 数据、运维及回退

新增两表及删除claim时清scope的触发器，重复初始化幂等。票号只控制排队，不是批准清单或文件进度。启动仅在DataGuard独占下清理旧运行票号并从任务状态重新调度；restore必须先完全停止队列。未知旧claim保持全局，不能将缺范围视为空范围。数据库回退不回退已经发生的文件操作，不为兼容而清除业务日志。

活动/等待摘要不返回内部路径；范围记录随私有数据库保存，不进入公开附件。合成测试验证不同连接FIFO、目录后代、旧claim、取消/恢复、HTTP播放、检查跳过、身份物化与不同模拟设备队列。尚不能替代实际跨卷、断盘、exFAT或完整任务竞争矩阵。后续补齐工作流后再评估A6-16整体验收。
