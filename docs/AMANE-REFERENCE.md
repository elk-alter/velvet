# Amane 源码对照与接入计划

研究基线：2026-11-02，主分支提交 [`99369d2`](https://github.com/sqzw-x/amane/tree/99369d2a862af2eb9a6f95a3d8e668057b7e49d0)。本次阅读源码与开发文档，未运行其完整应用，未把研究结果视为 Velvet 已实现的功能。

## 产品分工

Amane 以编号元数据为中心，提供多源聚合、来源审阅、分类治理和任务执行。Velvet 保持以本地收藏为中心，负责影片 → 版本 → 分段 → 文件、挑选、截图预览、重复对比和播放。通过公共 HTTP API 接入独立部署的 Amane，不直接读取或修改它的数据库，不把它的文件整理功能接到默认自动流程。

原视频继续只读；刮削结果、图片和任务记录放在 Velvet 的 data 目录。自动刮削不等于自动移动、重命名或删除文件。

## 源码对照

| 能力 | Amane 源码入口 | Velvet 现状 | 借鉴后的验收要求 |
|---|---|---|---|
| 字段级择优 | `src/amane/aggregate/engine.py`、`merge.py` | 已保存快照、部分字段锁；缺完整来源审阅 | 展示当前值、候选值、来源和更新时间；锁定值在重新同步后保留；空结果不清掉手工值 |
| 原始数据与手工值分离 | `src/amane/db/repos/metadata.py` 的 `_filter_locked`、写入模式 | 同步与手工编辑保护为原型 | 保留最新远端快照；手工覆盖单独存储；解锁后的行为明确；同一影片多版本共享资料但保留文件技术信息 |
| 任务树与可靠入队 | `src/amane/scheduler/worker.py`、`src/amane/api/routes/tasks.py` | 有 SQLite 刮削任务和远端轮询，部分流程依赖内存状态 | 批量任务显示逐项结果；提交超时先核对再重试；应用重启后对账；取消后不误报成功；只重试失败步骤 |
| 标签与别名治理 | `src/amane/db/facet_rules.py` | 有来源标签、规则标签、别名配置和理由 | 来源标签、规则标签、用户标签分别保存；支持规范名、别名、屏蔽；预览影响数量再应用；重新刮削不复活屏蔽标签 |
| 多维筛选与分页 | `src/amane/db/repos/metadata.py`、`web/src/routes/meta.index.tsx` | 多数筛选依赖前端全量资料 | 服务端筛选、计数、稳定排序和分页共用条件；结果数量可信；返回详情后保留筛选和滚动位置 |
| 保存查询 | `src/amane/agent/saved_query_ops.py`、`web/src/routes/saved-queries.*` | 待开发 | 将组合条件保存为动态片单；新增影片自动进入匹配片单；条件可直接查看和编辑 |
| 图片资源与来源 | `src/amane/media/resource_store.py`、`src/amane/api/routes/resources.py` | 已缓存封面/海报，有重试原型 | 图片下载与元数据成功分别结算；支持换封面、失败重试；本地截图与远端图片分别标记；保留已可用图片 |
| 视觉语义检索 | `src/amane/semantic/`、`src/amane/db/embeddings.py` | 尚未实现 | 先完成普通筛选；后续可选本地索引，只在筛选候选集中排序；模型未就绪不影响普通浏览 |
| 自然语言助手 | `src/amane/agent/` | 尚未实现 | 优先把自然语言转换为可检查的筛选条件；不允许模型直接执行任意 SQL 写操作或删除媒体 |

上述入口以研究提交为准，不代表其内部类或数据库结构是稳定集成契约。

## 优先交付顺序

1. **可靠刮削与结果审阅**：先拆出 Amane 客户端，增加服务版本/连通性诊断、请求超时分类、响应校验；补齐字段差异预览、锁定、图片状态、重启对账与批量重试。验收包含断网、提交结果未知、图片失败、空字段、字段锁、同片多版本和服务重启。
2. **标签治理与筛选闭环**：提供标签管理页、别名/屏蔽预览、批量应用、清晰的包含/排除条件、服务端计数分页与保存筛选。规则生成标签必须能查看理由，手工标签不被重新分类覆盖。
3. **自动发现与增量更新**：文件稳定后才入队；目录监听配合定期增量对账；只处理新增或资料不完整条目。目录失联与文件删除分别处理，避免 NAS 掉线触发误清理。
4. **人物与图片体验**：人物稳定身份和别名、头像缓存、人物作品聚合、封面选择与截图重采样；评分收藏与资料更新分离。
5. **可选 AI 检索**：自然语言筛选优先于视觉索引。明确模型位置、首次下载、资源占用和数据发送边界，再考虑 NAS 的可选推理部署。

本轮是源码研究与需求补充，以上条目均未据此改标为完成。

## 接口边界

- 现有 `/metadata`、`/tasks`、`/resources` 调用集中到客户端适配层；按安装版本验证请求、状态枚举、分页与图片授权方式，不以主分支文档推断本机版本一定兼容。
- 元数据同步、图片获取、技术信息探测、截图分别记录结果，部分失败不撤销已成功步骤。
- 不逐文件重复刮削同一编号；本地按影片关联结果，同时核对远端提交的真实契约，不能假设服务器会替客户端去重。
- 原始编号、规范编号、远端条目 ID 和本地影片 ID 分别保存；模糊匹配交给审阅，不自动合并身份不明的影片。
- Windows 本机继续使用服务端目录选择；将来部署 NAS 后，浏览器选择的是服务器挂载目录，不能把浏览器本机路径当作服务器媒体路径。
