### 硬盘管理必须走通的用户场景

1. **散落文件收拢**：连接两块盘，盘点多个目录，筛选已识别作品与待确认文件；纠正目录名作为片名、分集和版本归属，生成统一结构。
2. **先小批验证再批量整理**：选几项查看新旧路径、资源归属、数量/字节和冲突；确认后实际复制、校验并绑定，复核通过后可对冻结的更大范围执行。
3. **原盘内部整顿**：按规则改名/移动，包含仅大小写变化及名称互换；字幕等明确归属资源同步处理；支持撤销且不覆盖后来出现的文件。
4. **换盘与离线管理**：目标盘整理成功后默认保留源；可切换播放位置。拔盘仍能查看快照，重新连接/盘符改变后核实设备并继续任务；不可用位置不误判删除。
5. **异常后复核**：取消、重启、空间不足或绑定失败后，逐项区分已提交与待处理；恢复不重复搬运，撤销范围清晰，片库收藏、进度与人工修正保持一致。

以上场景必须能由界面完成，不接受仅命令行、内部类或测试脚本作为用户功能交付。真实用户硬盘操作仍须在产品内批准具体计划；开发验收使用合成媒体。

### 不纳入本版的内容

永久删除、无人确认的全盘搬迁、任意字节断点续传、自动下载更高清替代文件、通用视觉AI识别、转码、完整NAS/ARM认证和安装器。质量与保留偏好用于辅助决策，不自动删除原文件。部署结构继续兼顾未来NAS网页访问，首发验收以Windows本机为准。

## 版本目标与完成定义

用户能在一个工作区管理多块硬盘上散落的视频：盘点和查找 → 识别/归组/比较 → 选择统一目录规则 → 审阅改动 → 确认并执行 → 校验及片库绑定 → 复核结果，必要时恢复或撤销。

**只有盘点、生成计划、导出JSON，或只能复制却丢失片库关系，都不能算完成。** alpha.6必须交付安全复制、同盘重命名/移动、跨盘整理及可恢复任务；默认跨盘先复制并保留源，源归档另行确认。永久删除不纳入本版。

本次是规划授权，不是执行用户真实硬盘整理的授权。现有AGENTS只读约束继续用于开发和测试。开发执行器前须增加操作模式ADR及测试目录写入约束；成品仅对用户在产品内确认的具体计划执行写入。不能将整个源目录默认为可任意写入。

## 实施顺序与发布门禁

1. 位置/文件身份及执行日志模型、租约/恢复ADR；alpha.5迁移样本。对应01–04、08、13、16–19。
2. 服务端查询与独立工作区并行推进；统一选择/规则契约。对应05–07、20–25。
3. 先在合成目录完成复制→校验→提交→绑定，再完成同盘改名/移动、跨盘整理、取消/恢复/撤销；09–19不得只交正常路径。
4. 全流程浏览器、性能、NTFS/exFAT、故障和升级演练，完成27–30，最后发布。

这里的“并行”指实施依赖可并行，不授权启动额外AI代理。数据模型/执行器前置于真实磁盘写入；本次规划不运行任何源文件操作。

发布硬门槛：至少一个多盘小批量场景完整走完 **批准计划→真实文件操作→完整校验→片库保真→断盘恢复→结果复核**；另一个同盘整理样本完成改名/移动与撤销。全部P0均须有证据。不可用“后续再接执行器/绑定/恢复”放行alpha.6。确需变更必达范围须回到用户确认，不能自行降级。

## 与旧Epic及后续版本的关系

alpha.5交付与延期记录不改写。ORG-21–30由alpha.5条件/后续调整为alpha.6必达（源归档ORG-31纳入受控、可恢复部分）；ORG-01–20、32–35是需完善和回归的前置，不视为从零新增。永久删除、任意文件系统字节续传、无人确认的全盘搬迁均不纳入。

alpha.7保留识别证据、问题级审阅、标签/人物治理及隐私增强；本版仅修复整理闭环依赖的问题，不提前承诺通用AI语义理解或外部最高画质发现。
