# 网络检测、来源配置与媒体库

本批继续参考 Amane `99369d2` 的来源级检测、拦截页判定与媒体库自动化分工。实现适配 Velvet 的标准库 HTTP 服务与现有数据库，没有引入 Amane 整套数据库或管理界面。

## 网络检测

侧栏进入“网络检测”，点击“检测当前来源”。先在“资料源与目录”保存引擎和代理，再检测；未保存的输入不参与探测。

- 内置模式只检测已启用来源；可对单个来源重测。最多并发三项，逐项返回结果、HTTP 状态及耗时。
- 与刮削使用同一代理和 HTTP 传输，识别空响应、验证页、地区限制、年龄确认页面、限流、连接失败和超时。来源页即使返回 HTTP 200，也不一定报告成功。
- 未知或已禁用来源标记为“未检测”，不影响其它来源结果。网络结果保存在进程内，重启后清空。
- 外部模式读取该实例的配置路线，并调用 Amane 的真实来源检测接口；连接失败时报告服务不可用，不伪造站点检测结果。
- 检测不提交刮削任务，不发送本地影片编号或媒体。来源首页可访问只代表当前探测入口可访问，不保证详情页、图片或某个编号可用。
- 当前没有浏览器渲染/验证解决器，遇到验证页会报告原因，不自动绕过。

2026-11-02 经已配置的本机 HTTP 代理实测，三个内置来源首页均返回 HTTP 200 且通过页面判定；这是当次检测结果，不代表持续可用。

## 刮削来源

“刮削来源”先显示完整目录与两种执行方式；在内置配置中用勾选、上下按钮和字段下拉框调整来源。范围见 [来源目录与管理页面](SOURCES-AND-UI.md)。普通编号使用启用的普通来源，FC2 编号使用对应来源，禁用来源不会被请求。字段优先来源无值时，继续按默认顺序补全；禁用来源不会因字段配置而重新启用。

这些配置用于下一次执行的任务；修改配置不会覆盖已同步的手工锁定字段，也不会自动取消正在执行的任务。强制重新刮削沿用现有条目操作。尚不支持不同来源语言版本、站点级持久缓存复用或所有上游采集器。

## 媒体库

侧栏“媒体库”显示名称、服务端路径、在线状态、文件数、匹配数、缺失数和上次扫描结果。已有监控目录自动以原目录显示，不移动媒体，也无需重新导入。选择“查看文件”可按标题/编号和匹配、缺失、处理提示筛选，分页进入文件详情。

创建或配置媒体库时可设置名称、自动化、排除通配符、最小文件大小及距最后修改时间的等待秒数。新增媒体库不允许目录相互包含；历史重叠目录按最长根路径归属文件，避免统计和任务重复。

| 自动化模式 | 定期扫描 | 新资料自动刮削 | 手动扫描/刮削 |
|---|---|---|---|
| 关闭 | 否 | 否 | 可用 |
| 仅扫描 | 是 | 否 | 可用 |
| 扫描并刮削 | 是 | 需要同时开启全局自动刮削 | 可用 |

自动化调整只影响后续发现与入队；已进入队列的任务仍需从任务中心取消。新库默认等待 30 秒；旧目录保持原有零等待行为。等待依据文件修改时间，不能替代下载客户端的完成信号。扫描仍为定期轮询，尚未实现原生文件事件监听。

排除规则使用相对路径或文件名通配符，例如 `sample*`、`*/sample/*`。排除和最小大小限制只影响后续扫描与自动入队，不删除现有记录。扫描单库只处理所选根目录；离线目录保留已有记录，目录遍历出现权限错误时不更新该库缺失标记。停止监控保留索引和原文件，并阻止该目录后续自动入队。

本批不引入文件整理落盘、重命名、删除、CloudDrive webhook 或 RSS 发现，原视频继续只读。

## 接口与验证

- `POST /api/network/check` 启动检测，可传 `source_ids`；`GET /api/network` 查看进度与结果。
- `POST /api/scraping-options` 保存来源及字段优先级。
- `GET/POST /api/libraries` 列表或保存配置；`POST /api/library-scan` 扫描单库。
- `GET /api/library-files` 按库、状态和搜索条件分页；停止监控沿用 `/api/remove-folder`。

全部修改接口沿用现有鉴权与 CSRF Token。媒体库设置存储在主数据库的 `library_settings`，随主片库备份；恢复旧数据库时重新建立缺失的设置表。配置和私有路径不进入 Git。

测试包含模拟拦截页、200 空响应、限流、未知/禁用来源、部分失败、字段回退、配置校验、单库扫描、排除、离线保留、仅扫描不入队和停止监控后不入队。NAS 实机与浏览器完整交互尚需额外验收。
