# alpha.6 升级与受控回滚演练

日期：2026-11-05。范围：A6-29、A6-17和28的相关回归。Windows本机NTFS、Python3.10.6，全部使用自动新建的合成目录及独立应用数据，不操作生产服务或真实媒体。

## 可复现命令

```bash
python scripts/rehearse_upgrade.py
python -m unittest test_upgrade_preservation test_restore_reconciliation test_full_backup test_video_ids test_organization_http -q
```

演练默认从Git中alpha.5发布提交44f7373提取旧程序；可显式指定--baseline。需要已有Git历史，源码包内没有Git历史时仍可运行不依赖Git的单元测试。运行结果只输出数量和布尔摘要，不输出私人路径、凭据、图片或OCR文字。脚本中的assert是验收门禁，不使用python -O。

## 实际链路

1. 用旧程序初始化数据，填充两份合成媒体及18类资料；生成完整双库、配置、图片和OCR证据备份。
2. 当前程序重复初始化与启动对账两次。运行中的剧照和检查转为排队；扫描运行记录转中断；来源未确认/已切换的刮削任务转为needs_review，不能自动再次提交。所有外部请求被测试替身拒绝。
3. 从固定盘点批准复制一集及明确归属NFO/字幕，再同盘移动、完整核对、绑定；每一步核对人工资料与图片证据。已移动时恢复旧完整快照被拒绝，应用库和文件位置保持当前状态；不是仅测预览提示。
4. 独立批准反向恢复源位置，再次核对资料；用模拟来源只执行两个可恢复的内置任务，已完成/失败/取消任务不重放。
5. 普通恢复仍因物理历史被拒绝；生成文件日志对账后，恢复旧完整快照，保留三个复制目标、当前完整回滚目录和私有审核回执。
6. 比对恢复后的18类资料、内置库4张表的全部原始记录、两个原配置文件字节和6个图片证据文件SHA；再由旧程序初始化并对账读取。核对全部源文件哈希/mtime_ns及非任务哨兵。

## 核对对象

|范围|证据|
|---|---|
|作品与身份|videos全部字段，含标题/演员锁、来源快照、收藏评分、播放进度、已看、内容覆盖值；人工作品/版本/分段及首选播放记录|
|用户决策|人物评分收藏/资料、分类收藏、目录合集规则、媒体库策略、精确排除、重复保留及历史、关系撤销、应用状态|
|质量与OCR|人工更新标记/备注/接受决定、自动发现、generation、尝试次数及dismissed覆盖值；移动后读取不会使已驳回结果重新出现在问题列表|
|图像|封面、海报、本地截图、剧照、人物头像、analysis目录下对应generation的证据帧，6文件SHA一致|
|来源与队列|主库完成刮削、完成剧照和质量记录不变；可恢复状态按既有契约转换；内置tasks/metadata/source_cooldowns/source_cache全记录快照恢复，冷却和来源缓存保留|
|原媒体与资源|源两份合成媒体、专属NFO/字幕、非任务哨兵；反向后名称/哈希/mtime一致，复制副本不被数据库恢复删除|

18类为脚本显式填充并逐字段核对的权威资料表，不把运行队列的必要状态转换算作数据损坏。图片是合成PNG字节；本演练核对缓存保真与关联，不宣称执行了真实OCR识别或图片解码。

## 判定及边界

当前A6-29规定的旧完整快照→两次迁移→整理与恢复→受控回滚→旧程序读取链路已在此合成NTFS样本通过；这是受控回滚验收，不能用旧程序原地打开尚有未完成物理状态的新库。恢复前对账门禁及限制见ADR0009和操作指南。

自动回归还会先改变图片、收藏评分、OCR覆盖决定与内置任务结果，再完整恢复并逐项核对，随后重新对账和模拟执行，防止空备份或只测未变化值产生假通过。

不替代A6-27的真实exFAT/拔盘、A6-28全部故障边界、A6-22性能和A6-30源码包/完整浏览器/最终发行验收。不验证任意历史版本、NAS/ARM、外部来源在线可用性、浏览器localStorage的隐私开关迁移或无数据目录的灾难恢复。完整目标和未完成项仍见需求与交付台账。
