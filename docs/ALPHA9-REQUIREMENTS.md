# alpha.9 硬盘统一管理

以 v0.1.0-alpha.8 为基线。沿用既有盘点、固定计划、执行日志、文件身份证明和恢复流程。本版优先把各入口串成一个可核对的整理流程。

| ID | 优先级 | 场景与验收 |
|---|---|---|
| A9-01 | P0 | 从多个盘点位置建立固定计划。支持跨页勾选、全选后排除和修改所选目标相对路径。完整校验和最终确认中的文件范围与选择一致。 |
| A9-02 | P0 | 完整校验前检查所选范围。逐源显示在线状态、文件数及字节数，并说明已知冲突、目标新增空间、伴随资源和预留空间。一般容量读取失败显示未知，明确的权限拒绝显示权限受限。 |
| A9-03 | P0 | 从执行任务回看已批准清单和当前入库位置。清单可分页阅读，已批准的历史页面提供返回任务入口。已跳过、未提交、未绑定或关联已删除的条目不显示入库入口。 |
| A9-04 | P0 | Windows 合成媒体验证多源选择、完整校验、批准、复制、已验证绑定和撤销。分别验证真实 NTFS 跨卷、校验中断后恢复、同盘移动及反向撤销，核对源文件、字幕和非任务文件。 |
| A9-05 | P0 | 保留 alpha.8 数据兼容性。完成 HTTP、桌面及 390px 浏览器验证和全量回归；发布时执行解压包、升级回滚和本机部署核对。 |
| A7-10 | 条件验收 | 有实盘后验证拔盘、重插、换盘符、exFAT 和多分区。仅有内置卷时，记录实际测试环境和剩余设备覆盖。 |

容量和冲突摘要使用已保存的只读预览，按当前选择聚合并读取目录状态及可用空间。用户修改目标相对路径后，完整校验使用重新生成的固定预览。批准仍绑定所审阅的清单，执行前沿用现有证据核验与故障保护。

继续使用既有操作语义。复制保留源文件，同盘移动按反向计划恢复原位，复制绑定撤销保留两份物理文件。真实媒体整理仅经用户审阅并批准具体计划。

开发与验收按 [交付台账](DELIVERY-STATUS.md) 和 [开发流程](development/README.md) 记录。标签、人物治理与 NAS 在各自迭代交付。
